# Wi-Fi 调试与网页 OTA

本组件负责 Wi-Fi、HTTP 和 OTA。信号资料、设置及升级后的保留/清理策略由独立的 `components/user_data` 组件管理；射频暂停/恢复由应用层注册回调。

进入“调试”，按中键到“开始调试”，再按中键启动。显示“已开启”后再按一次中键即可关闭热点和网页，也可点击预览中的按钮切换。启动、关闭使用后台任务，界面通过 50 ms 定时器读取状态，不跨任务调用 LVGL。退出调试菜单后热点继续运行，设备重启后默认关闭。固件正在上传或等待重启时不接受关闭请求，避免中断升级。

- 热点：`RF-Manager`
- 密码：`rfmanager123`
- 网页：`http://192.168.4.1`

手机或电脑连接此热点即可使用，无需连接路由器或互联网。热点密码可在 `include/debug_ota.h` 修改；上传接口只在设备热点服务中开放。

## 第一次使用

本次将 Flash 改为 `partitions.csv` 中的双 OTA 分区：保留 24 KiB NVS，新增 otadata，应用从 0x20000 开始，两个应用槽各 0x1e0000（1.875 MiB）。**第一次必须通过串口执行完整 `idf.py flash`，包括引导程序、分区表、OTA 初始数据和应用**。旧单应用分区下不能直接 OTA 到本布局。

网页只上传 `build/ESP32S3_A07_CC1101.bin` 应用镜像，不能上传 bootloader、partition-table、ota_data_initial 或合并镜像。后续 OTA 不改分区表；若再次调整布局，仍需串口烧录。

## 上传流程

网页展示设备版本和可上传大小，使用原始二进制 POST `/api/ota`，带 `Content-Type: application/octet-stream` 和 `X-RF-OTA: 1`。浏览器和服务器均检查芯片、应用描述和项目名称；服务器还检查分区大小，并在完整镜像校验成功后才切换启动分区。错误或传输中断不会切换分区；已收到的数据写在备用槽，旧应用继续可用。

### 用户资料与设置

“保留用户资料”默认勾选，保留 `signals` 命名空间内的信号；取消后清空信号库。“重置设置”默认不勾选，勾选后清空 `settings` 命名空间，当前可持久化的亮度恢复为 70%。两项独立。对应请求头 `X-RF-Retain: 1/0`、`X-RF-Reset: 1/0`，缺省为保留、不重置。

完整镜像通过校验后才在 `upgrade` 命名空间记录待执行选项。新应用完成初始化、确认镜像有效后才清理指定数据；回滚到旧槽会取消清理意图并保留所有资料。清理失败保留意图，下次启动继续执行，绝不通过擦除整个 NVS 恢复错误。亮度停止调节一秒后保存，减少连续写 Flash。

## 信号管理

网页读取实际 NVS 信号库，支持重命名、修改键码、删除、单个导出、选中批量导出、全部导出。导出为带格式标识、版本和完整记录的 JSON，保留频率、协议、原始数据等已有字段。名称最多 63 UTF-8 字节，键码为 1～128 位十六进制字符串，保留前导零。修改名称、键码后需按“保存”，导出使用已保存的数据。

- `GET /api/signals`：完整信号数组。
- `POST /api/signals/update`：`{id,name,key_code}`，只替换两个字段。
- `POST /api/signals/delete`：`{id}`，删除确认后执行。
- 修改请求须带 `X-RF-API: 1`。NVS 提交失败返回错误，不报告保存成功。

`user_signal_save()` 已由射频接收流程调用。独立 signals NVS 分区 128 KiB，库上限 32 条、JSON 总量 48 KiB，使用 blob 避免 NVS 字符串 4000 字节限制，并保留原子更新所需空闲空间。旧库首次修改时迁移，清空信号库会保留空库标记，避免旧库重新出现。仅旧分区表时退回 8 KiB 兼容容量；新增分区首次必须串口烧录。RAW 键码只读，已知 OOK_PWM 改码会重建 raw 波形。初始化不擦除用户资料。

OTA 写入前暂停并锁定射频活动，失败后解除锁定，不自动恢复发送。成功后两秒重启。新固件完成 BSP、显示和定时器初始化后才确认 OTA 镜像；启用引导程序回滚机制，未通过初始化的新固件在后续重启时可回退。升级后需再次在屏幕上启动调试并连接热点。校验用于识别错误镜像和损坏数据，当前没有启用固件签名验证。

前端上传进度表示传输进度，100% 后仍需等待设备校验结果。升级时应保持供电及连接。PC 的 LVGL 预览只模拟按钮状态，不会启动真实热点。

## 验证

- `node tests/check_ota_page.mjs`：使用实际编译固件验证前端，覆盖信号编辑/删除/导出/选择、保留附加字段、非法输入、默认升级选项、升级期间禁用编辑、错误镜像和失败重试。
- `python tests/check_user_data.py`：编译实际存储代码与 SDK cJSON，用内存 NVS 替身验证 CRUD、提交失败、容量、四种升级选项、未确认启动、回滚和清理重试；不代表实板断电测试。
- `python tests/preview_ota_web.py`：在本机 127.0.0.1:8765 预览网页样式，设备信息和两个信号为标明的模拟值，POST 返回 405，不执行升级或真实修改。
- 实板需串口初次烧录后验证热点、网页上传、成功重启、再次更新和异常中断后的旧固件可启动性。
